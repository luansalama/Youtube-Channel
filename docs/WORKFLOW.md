# Workflow — v0.3.6

Minecraft Narrative Studio is video-at-a-time and dashboard-controlled.

## Daily use

1. Double-click `START-STUDIO.vbs`.
2. Read the single next action on Production.
3. Open Workspace.
4. Edit manually or request a Studio Assistant proposal.
5. Review, apply, and run checks.
6. Complete physical production work and register evidence through the dashboard.
7. Approve only the five consequential locks.
8. Package, dry-run, and publish from Release.
9. Import performance evidence and record lessons.
10. Close Studio from the sidebar.

No terminal or manual JSON/CSV editing is required during normal operation.

## Seven phases

| Phase | Main workspace | Human approval |
|---|---|---|
| Direction | promise, premise, Minecraft causality, scope, research decision | Direction |
| Story | causality, audience presentation, characters, scenes, continuity, ending | Story |
| Script | production script, revision evidence, spoken-pass notes | Script |
| Production | build, assets, shots, risks, capture and selected takes | automatic |
| Edit | picture, sound, captions, QC and real master | Final master |
| Release | title, thumbnail, metadata, package and publication settings | Publication |
| Learn | analytics, observations, hypotheses and next-video decisions | automatic |

## Assistant autonomy

Pending proposal documents can be edited and saved in the dashboard before acceptance. The assistant may draft and organise the current phase, but it submits proposals rather than directly replacing work. It may not fabricate physical completion, approvals, uploads, analytics, rights clearance, or commercial commitments.

## Single active video

A second active production cannot be created. Pause, complete, abandon, or finish the current production before starting or resuming another.

## Revisions after approval

Use **Reopen an earlier phase** in Workspace. Provide a reason. The harness invalidates the affected and downstream approvals and retains the history.
